## Goal

Make AI suggestions easy to actually implement — without losing the developer-facing code. Two additions:

1. **Visual before/after previews** — show exactly what the change looks like, not just text.
2. **Platform-specific implementation steps** — short, ordered "where to click" instructions tailored to the user's stack (WordPress, Shopify, Webflow, Wix, Lovable, raw HTML, Next.js/React, etc.) — alongside the existing code snippet.

Code stays visible (audience is mostly developers) but is paired with a real preview and concrete implementation path.

## What changes per AI panel

### 1. SEO Content Rewrites — add Google SERP preview
Each rewrite (meta title, meta description, H1) gets a **before/after card**:

```text
┌── Before (your site now) ──┐   ┌── After (AI suggestion) ──┐
│ example.com                │   │ example.com               │
│ Old title (gray, faded)    │   │ New title (bright)        │
│ Old description...         │   │ New description...        │
└────────────────────────────┘   └───────────────────────────┘
```

Rendered as a faithful Google search result mock (favicon, breadcrumb URL, blue title, gray description, correct fonts/sizes). H1 gets a separate "page heading" preview block.

### 2. Conversion Booster — add hero preview
Each of the 3 variants renders inside a mini website hero mockup (large headline, supporting text, fake CTA button) using the project's design tokens. User instantly sees how the copy *feels* on a page, not just reads it.

### 3. Smart Fixes — keep code, add platform steps
Below each fix's code example, add a collapsible **"How to apply this in {platform}"** block with 3–6 numbered, plain-English steps generated by AI for the user's chosen platform.

### 4. Product Draft — add storefront preview
Show the generated name/description in a fake product card (image placeholder, name, price, description) so the user sees how it reads as a real listing.

## Platform selection (one-time, persisted)

After the initial scan, show a small **"What's your site built with?"** picker at the top of the AI section:

```text
WordPress · Shopify · Webflow · Wix · Lovable · Next.js/React · Plain HTML · Other
```

- Default guess: detect from the scraped HTML (look for `wp-content`, `cdn.shopify.com`, `webflow.com`, `__NEXT_DATA__`, etc.) in `run-seo-agent`.
- User can override with one click.
- Selection persists in `localStorage` so they don't re-pick on every scan.
- The selected platform is sent to `ai-smart-fixes` so steps are tailored.

## Backend changes

- **`run-seo-agent`**: add `detectedPlatform` field (best-guess string or `"unknown"`) to the response.
- **`ai-smart-fixes`**: accept new `platform` field; prompt the model to produce `implementationSteps: string[]` (3–6 short steps) per fix, in addition to existing `personalizedFix` + `example`. Tool-calling schema updated.
- No changes needed to the other 3 AI functions (previews are pure frontend).

## Out of scope

- Direct apply to platforms (CMS APIs, OAuth) — explicitly deferred.
- PDF export / email sharing — explicitly deferred.
- Showing a full screenshot of the user's actual page (heavy, needs Firecrawl/Puppeteer). The previews are platform-agnostic mockups using their content.
